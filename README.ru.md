# gftp-smb-git

*[English version](README.md)*

gFTP, собранный из upstream git с четырьмя патчами:

- **`gftp-cifs.patch`** — бэкенд SMB/CIFS с чтением и записью, на базе
  [libsmb2](https://github.com/sahlberg/libsmb2).
- **`gftp-ru-translation.patch`** — восстанавливает русский перевод, потерявший около 101 строки при
  перегенерации каталогов PO, и добавляет русские записи в файл `.desktop`.
- **`gftp-wayland-icon.patch`** — заставляет окно представляться как `gftp`, а не `gftp-gtk`, чтобы
  оболочки Wayland сопоставляли его с `gftp.desktop` и показывали иконку. Без него окно и его запись
  в панели остаются без иконки — например, в labwc с sfwbar.
- **`gftp-smb-ru.patch`** — русский перевод строк самого бэкенда SMB. Накладывается последним:
  переводимые строки появляются только после `gftp-cifs.patch`, а сам `po/ru.po` до этого переписывает
  `gftp-ru-translation.patch`.

Пакет конфликтует и с `gftp`, и с `gftp-git`, поскольку устанавливает те же файлы.

## Требования

Бэкенду SMB нужен `libsmb2`, доступный сейчас только как пакет AUR `libsmb2-git`:

```
git clone https://aur.archlinux.org/libsmb2-git.git && cd libsmb2-git && makepkg -si
```

Дальше пакет собирается обычным `makepkg -si`.

## Как пользоваться бэкендом SMB

Схема — `smb://`, а **не** `smb2://`. В комментариях к заголовкам самой libsmb2 написано `smb2://`,
но её разборщик URL такую запись отвергает.

```
smb://сервер/ресурс/путь     конкретный сетевой ресурс
smb://сервер/                список ресурсов сервера
```

`gftp-text` работает так же:

```
gftp-text smb://сервер/ресурс/
```

### Учётные данные

Указывайте реальные имя пользователя и пароль. **Анонимные и гостевые сеансы не могут подключиться к
серверу, который требует подпись SMB**: такие сеансы не вырабатывают ключ сессии NTLM, подписывать
нечем, и сервер отклоняет соединение. Windows-серверы обычно настроены именно так, Samba — как
правило нет.

Если учётная запись живёт в домене, отличном от домена самого сервера, укажите домен в имени
пользователя через **точку с запятой**:

```
CORP;ivanov
```

При ошибке подключения gFTP выводит эту подсказку рядом с сообщением. Само сообщение libsmb2 в такой
ситуации обычно бесполезно: библиотека закрывает свой контекст до того, как сообщить о сбое, поэтому
настоящая причина затирается строкой `Read from socket failed, errno:9. Closing socket.` Не гоняйтесь
за этим errno — это артефакт, а не причина.

### Параметры

На вкладке «SMB» в настройках доступны три параметра:

| Параметр | По умолчанию | Действие |
|---|---|---|
| Требовать подпись SMB | выкл. | Включает подпись даже тогда, когда сервер её не требует. Если сервер подпись *требует*, она согласуется автоматически, поэтому параметр служит для ужесточения политики, а не для лечения ошибок подключения. |
| Требовать шифрование SMB3 | выкл. | Отказываться работать без шифрования транспорта SMB3. |
| Тайм-аут операций SMB | 0 (отключён) | Прерывать операции SMB по истечении указанного числа секунд. |

## Известные ограничения

- **Нет DFS.** libsmb2 не реализует перенаправления DFS, поэтому пути через пространства имён DFS не
  разрешаются.
- **Нет SMB1.** libsmb2 говорит только на SMB2 и SMB3. Это сделано намеренно: SMB1 устарел и небезопасен.
- **Время файлов не сохраняется при выгрузке** — `set_file_time` не реализован.
- **Кнопка «Стоп» не прерывает выполняющуюся операцию.** Синхронные вызовы libsmb2 не прерываются
  сигналом; используйте вместо этого тайм-аут операций.
- **Принтерные ресурсы отображаются как обычные каталоги.** Перечисление ресурсов использует
  SHARE_INFO_1, где тип ресурса не передаётся.
- **Кэш каталогов отключён** — каждый листинг обращается к сети.
